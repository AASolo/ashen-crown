# Архитектура кода — Ashen Crown

Стек: **TypeScript 5.9 (strict) + Vite 6 + Phaser 3.90**. Рендер WebGL, при отсутствии — Canvas. Сборка в обычный `dist/` или в один HTML-файл (`vite-plugin-singlefile`). Весь арт рисуется процедурно при запуске, поэтому внешних файлов ассетов нет.

## 1. Слои

```
┌──────────── Сцены (Phaser.Scene) ────────────┐
│ Boot → Menu → Game ⇄ UI (параллельно)  Gallery│
└───────────────┬──────────────────────────────┘
                │ создают и обновляют
┌───────────────▼─────────────┐   ┌───────────────────────┐
│ Сущности (entities)          │   │ Мир (world)            │
│ Actor ← Hero / Enemy ← Boss  │◄──┤ DungeonGen → Level     │
│ Projectile, GroundEffect,    │   │ Pathfinding (A*, Flow) │
│ Wisp, GroundLoot             │   └───────────────────────┘
└───────────────┬─────────────┘
                │ вызывают
┌───────────────▼──────────────────────────────────────────┐
│ Системы (systems): Combat, Skills, Loot, HeroData, Save,   │
│ Input, Settings, Fx                                        │
└───────────────┬──────────────────────────────────────────┘
                │ читают
┌───────────────▼──────────────┐  ┌──────────────────────────┐
│ Данные (data): classes, skills│  │ Ядро (core): iso, rng,    │
│ enemies, items, stats         │  │ events (шина), Sfx        │
└──────────────────────────────┘  └──────────────────────────┘
          art/ — процедурная графика (Canvas 2D → текстуры Phaser)
```

**Правило зависимостей:** `data` и `core` ни от чего не зависят. `systems` зависят от `data/core`. `entities` — от `systems`. Сцены — от всех. UI общается с игрой через шину событий `bus` и публичные поля GameScene, но не наоборот.

## 2. Сцены
| Сцена | Ответственность |
|---|---|
| `BootScene` | ждёт веб-шрифт (не дольше 1,5 с), вызывает `registerArt()`: генерирует все текстуры и все анимации. `?gallery` открывает галерею |
| `MenuScene` | меню, выбор класса и сложности, настройки, управление, лор |
| `GameScene` | мир: генерация этажа, сущности, бой, лут, свет и тьма, камера, портал, сохранение. Цикл `update(dt)` |
| `UIScene` | HUD поверх игры: сферы, панель навыков, мини-карта, трекер, инвентарь, навыки, карта, пауза, смерть, сенсорные кнопки. `isOverUI()` гасит клики по миру |
| `GalleryScene` | арт-ревью всех ассетов, `window.__exportArt()` возвращает PNG |

## 3. Сущности (лёгкий компонентный подход)
Тяжёлый ECS для 100–200 объектов избыточен. Используется **наследование + данные**:
- `Actor` — позиция в мировых координатах (клетки), спрайт, тень, направление (S/N + зеркало = 4 стороны), статусы (горение, кровотечение, замедление, оглушение), `moveBy` со скольжением вдоль стен, `sync()` переводит координаты в экранные и задаёт глубину сортировки `(x+y)·16`.
- `Hero` — путь A*, базовая атака, навыки, уклонение, зелье, ресурс, перезарядки.
- `Enemy` — конечный автомат ИИ: `idle → chase → windup → lunge|shoot → recover`, аффиксы элит.
- `Boss extends Enemy` — фазы (60% и 25%), набор способностей с перезарядками, субтитры.
- `Effects.ts` — `Projectile`, `GroundEffect` (телеграфы и лужи), `Wisp` (призыв), `GroundLoot`.

Поведение навыков задаётся **данными**: `SKILLS[id].kind` (`melee | projectile | fan | dash | spin | groundAoe | summon | charge | slam | buff | trap | vault`), а `systems/Skills.ts` содержит по одному исполнителю на каждый `kind`. Новый навык — это строка в `data/skills.ts`, без нового кода.

## 4. Системы
| Система | Что делает |
|---|---|
| `Input` | клавиатура (2 схемы), мышь, геймпад и сенсор сводятся в один объект `Intents` на кадр, есть флаг `autoAim` |
| `Combat` | бросок урона героя, урон врагам (крит, статусы, отбрасывание, хуки легендарок), урон герою (броня, сопротивление, неуязвимость) |
| `Skills` | `castSkill(scene, hero, id, tx, ty)`: стоимость, перезарядка, исполнитель по `kind` |
| `Loot` | генерация предмета: редкость → база → аффиксы → имя с согласованием рода → легендарное свойство или сет; цены, разбор, улучшение |
| `HeroData` | сериализуемое состояние героя и чистые функции над ним: `computeStats`, `damageMul`, `dpsEstimate`, сумка, надеть/снять, ранги и таланты |
| `Save` | `localStorage` (+ мост `window.ashenNative` для Electron/Tauri): save/load/exists/wipe с версией формата |
| `Settings` | масштаб UI, схема, громкость, тряска, дальтонизм, субтитры, сенсорный режим |
| `Fx` | эмиттеры частиц, числа урона, слэши, кольца, вспышки, тряска |

## 5. Ввод
`InputController.poll()` вызывается раз в кадр и возвращает намерения. Источники: клавиатура → мышь (`pointerdown/move` в GameScene) → геймпад → сенсор (объект `touch`, его заполняет UIScene). `lastDevice` переключает автоприцел: с мышью навыки летят в курсор, на геймпаде и сенсоре — в ближайшего врага в конусе направления. Клик по интерфейсу не уходит в мир (`UIScene.isOverUI`).

## 6. ИИ
- **Поиск пути героя:** A* (8 направлений, без срезания углов, бинарная куча), повторный расчёт по таймеру при погоне за целью.
- **Толпа:** одно поле потоков (BFS Flow Field) от героя, пересчёт при смене клетки героя или раз в 0,6 с. Сотни врагов ходят за O(1) на врага.
- **Пробуждение:** дистанция агро + линия видимости (Брезенхем по стенам). Получив урон, враг просыпается.
- **Атаки:** у каждого типа свой телеграф и тайминги (`windup`, `recover`). Волк делает прыжок, жрец — снаряд, гуль — удар.
- **Расталкивание:** мягкая сепарация, поэтому враги не слипаются в одну точку.

## 7. Генерация уровней
`generateDungeon(seed, depth, theme)` возвращает `DungeonData { w, h, tiles, start, boss, props, spawns, traps, secret }`. Алгоритм детерминирован по сиду (mulberry32), поэтому этаж можно воспроизвести, а ежедневный Разлом получается из фиксированного сида. Алгоритмы и гарантия проходимости описаны в GDD, раздел 6. `Level` превращает данные в спрайты (пол — глубина −100000, стены и пропсы — по `(x+y)`), ведёт туман войны (`explored`), карту (CanvasTexture), отсечение по камере и прозрачность стен перед героем.

## 8. Инвентарь и предметы
`Item` — простой JSON (uid, base, rarity, ilvl, implicit, affixes, setId, power, upgrade), поэтому сохраняется как есть. Характеристики героя каждый раз вычисляются заново (`computeStats`) из класса, уровня, талантов, экипировки, улучшений и сетов. Кэшируются в `hero.stats` и пересчитываются по событию `EV.INVENTORY`. Перетаскивание в UI: `pointerdown` на слоте → порог 8 px → призрак иконки → отпускание над слотом.

## 9. Сохранения
- Ключ `ashen-crown-save-v1`, формат `HeroData` с полем `version` (сейчас 1; сохранение другой версии отвергается — при смене формата сюда добавляется миграция).
- Автосохранение: при входе на этаж, каждые 20 секунд, при повышении уровня, убийстве босса и смерти.
- Десктоп: если обёртка дала `window.ashenNative.saveFile/loadFile`, сохранение пишется в файл в папке пользователя (Electron `ipcRenderer` / Tauri `fs`).
- Облако (план): тот же JSON уходит на сервер по REST с подписью.

## 10. Свет
Тьма — CanvasTexture размером в 1/6 экрана. Каждый кадр она заливается цветом темноты, а свет вырезается радиальными градиентами (`destination-out`). Затем текстура растягивается на видимую область камеры. Работает одинаково в WebGL и Canvas и стоит одной маленькой загрузки текстуры за кадр. Прежний вариант через `RenderTexture.erase` в Phaser 3.90 под WebGL не работал: режим смешивания ERASE там не выставляется.

## 11. Мультиплеер (план)
- **Сервер:** Node.js + `ws`, авторитарный, 20 тиков в секунду. Общий пакет `shared/` (данные, генератор, формулы урона — уже чистые функции без Phaser).
- **Протокол:** клиент шлёт намерения (`Intents` + цель + номер кадра). Сервер шлёт снапшоты (дельты позиций, HP, событий) и события лута (личный лут: у каждого свой).
- **Клиент:** предсказание движения героя + сверка, интерполяция чужих сущностей (100 мс буфер).
- **Комнаты:** до 4 игроков, сид этажа выдаёт сервер, генерация детерминирована и на клиенте, и на сервере.
- Подготовка в коде уже есть: ввод отделён от логики (`Intents`), генератор чистый и детерминированный, `HeroData` сериализуемый.

## 12. Десктоп (Electron / Tauri)
- **Tauri 2** (рекомендуется: 5–10 МБ): `src-tauri/` и `tauri.conf.json` с `frontendDist: ../dist`, команды `save_game/load_game` на Rust, которые пишут в `app_data_dir`.
- **Electron** (если нужен Steamworks через `steamworks.js`): `electron/main.cjs` грузит `dist/index.html`, `preload.cjs` пробрасывает `window.ashenNative`.
- Полноэкранный режим, переключатель VSync и разрешение на 4K уже поддержаны масштабированием по devicePixelRatio.

## 13. Производительность
- Отсечение тайлов и пропсов вне камеры (`Level.cull`), пересортировка глубины только у движущихся объектов.
- Пулы частиц Phaser, числа урона ограничены по количеству.
- Тьма в 1/6 разрешения, Flow Field вместо A* для толпы.
- Цель: 60 кадров в секунду при 150 врагах на среднем ноутбуке и 45+ на телефоне среднего уровня.
